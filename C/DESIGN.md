# C 完整交付：实验、评测、归因与验收

本轮负责人：当前用户 C，由 Codex 协助。修改边界为 C/；统一集成目标仍为根 implementation/。设计与实现一次覆盖整个 C 职责，真实模型运行作为独立的执行阶段，不把设计完成、工具通过与模型验收混为一谈。

## 1. 目标与最终交付

C 对每个候选版本回答五个问题：能否复现、答案是否改善、代价是多少、泛化是否退化、是否可以交给集成人。最终交付为冻结实验清单、可复跑命令、完整性检查、逐题结果、配对差值、失败队列、资源/模板检查及保留/撤回建议。

| 模块 | 输入 | 输出/验收 |
|---|---|---|
| 实验冻结 | 原200题、已交接分组、代码与模型配置 | 全量/开发/回归/代表性子集；种子、来源哈希与组不可漂移 |
| 真实基线 | 固定实现目录、统一配置、明确调用范围 | 所有计划题完成；原 evaluate_case 得分；中止单列 |
| 过程证据 | 候选、选择、参数来源、API、SQL前后、拒答原因 | 原有最少诊断字段；缺字段列出，不能猜造根因 |
| 失败归因 | 得分、原 reason、过程证据 | 触发阶段/证据/待复核项/责任人；合理与错误弃权另行核实 |
| 版本配对 | 基线和候选完整记录 | 固定题目逐题分差、无时延分差、耗时、调用与控制组退化 |
| 泛化验证 | 经复核改写、实体重算、库外控制 | 继承源题组；派生独立报告；旧答案不用于新实体 |
| 资源/模板 | 被测源码、数据、索引和进程信息 | 数量/大小/深度、索引/检索、CPU/RSS；明确测量范围 |
| 集成验收 | 上述证据与原文件清单 | 提交、范围、真实/模拟区分、问题优先级、保留/撤回建议 |

## 3. 实验矩阵与执行顺序

一次冻结全部层次，后续按实验目的执行，不再临时决定“先做哪几题”。

| 层次 | 范围与重复 | 用途 | 付费/完成条件 |
|---|---|---|---|
| 工具合同 | CLI、评分边界、中断、写盘、密钥屏蔽、比较拒绝条件 | 工具可靠性 | 无模型；自动测试通过 |
| 免费全量诊断 | 原200题、固定改写/片段/库外、词汇因素 | 支持 A 的检索/模板实验 | 无模型；标签覆盖不冒充答案正确率 |
| 代表性开发 | 冻结 development 中20题，各一次 | 新模型/环境连接或候选定位 | 有费用；完整计划、硬限额、独立文件 |
| 开发回归 | development 全部题，各一次 | 开发中失分分布 | 有费用；原评分、固定控制组 |
| 固定回归 | regression 全部题，每题两次 | 版本配对及稳定性 | 有费用；不得按结果换题 |
| 全白盒 | 原200题，每题两次 | 最终候选的完整本地回归 | 有费用；另行批准范围，分轮记录 |
| 泛化套件 | 12改写、4已重算实体、4库外意图 | 语义保持、参数泛化和拒答 | 先免费检查，再按独立范围执行模型 |
| 正式聚合 | 白盒200×2与黑盒100×2 | 公式核算 | 缺黑盒/正式模型时保持未完成 |

词/token、短语、同义词组、字段、模板族及端到端各自保留实验粒度。一轮候选只改变一个主要算法因素，C 完整工具链建设不等于同时改变 A/B 算法。

## 4. 必须记录的合同

运行身份包括实现目录、Git提交、未提交状态、各模块SHA-256、数据SHA-256、评估器SHA-256、平台与依赖。模型包括请求名、响应名、endpoint、thinking/temperature、输出token上限、重试、请求硬上限；配置缺失标为未知。记录样本顺序、重复次数、schema预热与执行器缓存生命周期。

单题证据：case_id/组/来源、候选ID及分数、选择ID、参数来源、API条件、精调前后SQL、返回列与行数/错误、原评分reason、含时延分/无时延诊断分、各阶段耗时、实际请求与token。完整结果只在已有原始证据中按原采集范围保存，不能靠预览重建完整结果或重算成绩。

原评分函数保持不变。答案分类、最终分数分桶和时延分分别报告；“部分正确(100%)”可得5分，不能仅按字符串认定失分。请求计数只使用有来源的HTTP/模型事件，缺失不能报0。每题重复先取平均再求题目总分；不把重复当成独立题数。

JSON/CSV逐题检查点与摘要保留。基础设施异常/额度耗尽/人为中止属于不完整运行，不能把未完成题补0。报告写入不纳入单题query计时；任何额外采集开销照实说明。

## 5. 归因与责任交接

| 证据 | C 分类 | 下一责任人 |
|---|---|---|
| 有空候选诊断，但尚未证明模板能力 | 检索未召回触发，能力待核实 | A/C |
| 可答模板已有独立能力证明且不在候选 | 召回失败 | A |
| 可答候选存在但选错，且有选择证据 | 选择失败 | B |
| 参数缺失/来源不符/显式条件丢失 | 填参或条件门禁触发，合理性待复核 | A/B |
| 精调前后列变化与复核支持退化 | SQL精调退化；仅有变化时为待复核 | B |
| 资源门禁/模型拒答 | 拒答触发阶段，不自动认定误拒 | B/C |
| 答案正确而扣时间分 | 正确但超时；附各阶段耗时 | B/C |
| API/SQL执行异常 | 执行失败，先排查环境 | B/C |
| 缺诊断或证据互相矛盾 | 待复核 | C收集证据后分派 |

固定模板/已核实参数执行仅证明模板能力，不能计作自动选择或填参成绩。冻结模型输出回放是反事实诊断，不替换真实模型得分。

## 6. 比较与保留规则

默认仅比较完整运行，题集/数据/评分器/模型设置一致。六题对200题必须显式选择子集，输出只限这六题；运行顺序/缓存或配置不同则不给出受控加速结论。根目录20题与B200题分别展示，不生成“谁更好”的混合总分。

候选至少应改善预先声明的目标失分类，并检查原正确控制题是否退化；小样本/离线反事实只能支持扩大验证。最终保留决定依赖完整固定回归、泛化与资源；不能仅凭模板数量减少或一次变快验收。

公式核算为 0.7×黑盒原始分 + 0.3×白盒原始分 + 150-N，不归一化。工具只在两套完整题集、规定重复与一致模型合同可核实时给出“公式参考值”，不自行声明官方成绩。实际黑盒缺失时不计算虚构总分。

## 7. 资源、模板与原文件

- 目标：CPU；建索引≤60s、单题检索≤200ms；端到端追求3s，4s/6s按原函数扣分；统计P50/P95/最大与>4s/>6s比例。
- 记录评估进程CPU和峰值RSS，数据服务单独测量；无法测两者时写未测，不能由单进程低于2GB认定总内存合规。Mac/Windows本地诊断不证明正式环境合规。
- 模板目标150条，数量分150-N；单条紧凑UTF-8 JSON≤4096字节，容器嵌套≤4的具体计算方法仍待主办确认。工具报告所采用算法及超标条目，不擅改结构。
- 比较原执行器、评分器、服务、原数据与用例的冻结哈希；A/B允许修改文件变化属于版本差异，不称原文件损坏。

## 8. 本轮交付与外部依赖

本轮完成完整设计、冻结套件、现有真实证据分析、可审查失败队列、配对子集比较、原文件/模板审计和相应无模型测试。现有资产足够先产出有数值的完整开发评估，不需要重跑模型才能开始 C 的核心分析。

真实新增批量调用需要本机密钥、明确模型配置与当轮额度；既有另一轮的剩余额度不沿用。正式模型、重复/计时边界、模板层数、多结果评分需主办确认；黑盒需官方提供。它们是执行/正式验收依赖，不影响现在把 C 方案与离线功能完成。

本轮不修改根协作文档及 A/B 文件；设计中对 B 的新增字段需求作为交接清单，不直接替 B 改代码。
