## 为什么保留检索别名

直接删除索引文档会改变 BM25 的文档频率、平均长度与门禁，400条源措辞检查中出现其他候选集合变化。最终实现给保留项增加 `retrieval_aliases`：只含旧编号、原位置锚点、旧描述与示例，不含 API、SQL、默认参数或答案。它们不是额外可执行模板。

检索器以原顺序构建相同400份文档，保持词频、IDF、平均长度和原始排序；先执行原来的候选门禁及 top-k，再将旧编号归并并去重。因此返回结果恰为“原候选列表按映射去重”，不因空出来的位置额外补入未验证候选。052/054的不同检索措辞仍可检索到052；模型提示只展示保留模板。该处理不访问执行器缓存，不按问题或答案查表。

最终候选的 ID 全在198条库中，原 B 的按候选编号选择及占位符提取接口可读取这些条目，无需修改 B 代码。兼容检查只运行既有纯格式化/占位符函数，不代表真实模型选择已通过。新增元数据不改变官方最终 `api_call + sql` 接口。
