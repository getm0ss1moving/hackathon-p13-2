修改文件：`implementation/runbook_matcher.py`、参数回归测试及 B 文档。

实际复现的旧行为：紧邻中文条件的区域被抽为 `region_lab9可用区az9`，租户参数吞入剩余问题；必要参数缺失时删除 API 条件仍返回成功。已针对这些失败处理实体边界、必要参数完整性和示例默认值误用。

## 第三轮：选择拒答与 SQL 输出正确性

修改文件：B 的两个运行时文件、合同测试及文档。观察到旧版选择器返回 0 后仍使用 strong top1，且精调流程会删除合法 LIMIT；本轮只围绕决策/SQL 输出的正确性修复，不改模板库和检索器。

明确拒答或非法编号停止；IP 输出不要求 IP 过滤；同名实体包含 host/port 等子串时不误判资源类型。保留合法 Top-N、原输出别名和原模板 UNION；精调 SQL 在完整 schema 下由 SQLite EXPLAIN 编译，异常、未知列、跨表越界、多语句等回退到原模板。无占位符模板也进入公共校验与精调，这可能增加模型调用数，真实时延影响未测量。
