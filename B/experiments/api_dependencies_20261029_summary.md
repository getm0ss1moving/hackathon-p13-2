# 通用跨步依赖检查：可独立推进，候选默认关闭

**无需等待 A 的五项答复，B 已完成一个独立候选。** 源码为 `681f609`，只增加跨步条件检查，未接入 199 条模板。67 项回归在候选关闭、开启两种配置下均通过。但冻结历史路径中有一道合法空参考结果会因拒答失去 5 个无时延分，因此保留 `RUNBOOK_VALIDATE_API_DEPENDENCIES=0` 为默认值；没有宣称总分改善。

## 假设、改动与隔离

基线为 `549e6e8`，A 缓存检索器和 200 模板保持不变。原执行器遇到无可用前步值会省略依赖条件，并且忽略声明的步号，只读紧邻前步。此前 B 仅在补足资源覆盖的直接查找中检查首步，SQL 同时包含各资源时不受该检查保护。

本轮只在 B matcher 中新增 `_validate_api_dependencies()`，由 `RUNBOOK_VALIDATE_API_DEPENDENCIES=1` 显式启用，位置在填参、原资源查找检查之后、SQL 精调之前：

- 静态核对全部引用的语法、位置和步号。只接受原执行器实际支持的紧邻前步，不将 step 1 解释为可任意回溯，也不重写模板引用。
- 通过原 `_execute_single_api_call()` 顺序读取必要前缀。每个依赖字段至少有一个原执行器能够使用的值，否则在读取目标前拒答；三步链同样检查中间结果。
- 原执行器用真值筛选与 set 汇总依赖值；全部为 0/False/空值、或不可哈希的列表/字典，不当作已有效传递。普通参数的 0/False 行为未改动；有些记录缺值但仍有可用值时，保留原有集合筛选语义。
- 正常路径继续 SQL 精调和原 execute。原资源查找诊断保持兼容，新增失败记录为 `invalid_api_dependency`，细因在 `diagnostics.matching.api_dependencies`；日志只记录字段、步号和计数。

不修改原执行器、评分器、服务、数据、测试文件或 A/C 根实现；不推断新的关系，不编造空答案，不改变字段、操作符或关联值。没有依赖的调用不新增数据读取，候选关闭时不进入新分支。

## 实际验证

| 证据 | 结果与含义 |
|---|---|
| 完整本地回归，候选关闭 | 67/67，通过、无跳过 |
| 同一回归，候选开启 | 67/67，通过、无跳过；是同组重复配置，不是 134 个独立案例 |
| 网络守卫 | 允许本地 8080 和内存 MockTransport；外部请求尝试 0、真实模型请求 0 |
| 19 条跨步模板的固定原生输入 | 15 个有可用前步值，4 个被检查拒绝；不代表 15 个完整答案正确 |
| 历史已作答 159 路径 | 146 无依赖、12 通过值检查、1 拒答；历史 41 道拒答未重跑 |
| 正常实体控制 | 受控模型、真实 API、原执行器与原评分得到 5 分；仍走 select/fill/refine，源表和目标表各一次真实 HTTP，源读取复用原缓存 |
| 空前步控制 | 受控选择/填参后，在读取下一步和调用 execute 前停止；没有把提前选择拒答算成该机制通过 |

固定原生探针使用模板既有默认值作为夹具，不作为运行时参数依据。4 个拒绝分别为：`rb_021`、`rb_041` 空前步；`rb_093` 无可用 storagePoolId；`rb_130` 第三步写 step 1，与原执行器使用 step 2 不一致。后两者在 B 原正常流程中还可能先被资源门禁拒绝，探针不冒充模型实际执行轨迹。

历史路径中新增拒答为 `CMDB-033/rb_021`：旧单轮原分 4（含时延罚分），无时延分 5；固定旧 API 条件时，前步为空。候选拒答经原评分器为 0。这个 **−5 是冻结条件下的无时延风险**，不是新模型配对结果，也不改写历史全量 448.9/1000。它说明“阻止条件遗漏”不能直接当作总分收益；如何在不扩大读取的前提下保留合法空结果，需要继续独立设计和验证。

  .venv/bin/python -W error::ResourceWarning -m unittest discover -s tests -q

# 免费固定输入审计；输出到新文件，不覆盖旧结论。

  --output reports/api_dependencies_new.json

[测试记录](api_dependencies_20261029_tests.json)含两种配置的结果与测试/源码哈希；[固定输入记录](api_dependencies_20261029_audit.json)含 19 条模板及 159 条已作答路径的结构诊断；[探针脚本](check_api_dependencies_20261029.py)禁止模型并限制网络目标。最初测试中发现并修正了占位符识别、单模板检索夹具和服务启动时序问题；初始失败记录保留在本机 reports，未算入验收通过结果。

## 尚未证明与后续

原执行器仍可能吞掉 HTTP / 分页错误。本检查不保证目标读取成功、分页完整、关系语义正确或最终答案正确，也没有解决 `rb_126` 最后一步的 HTTP 414；审计只读取依赖前缀，不能据其 HTTP 失败为 0 推断整条路径无错误。前缀读取计入 query 阶段，尚无新的端到端时延或正式资源结论。
