当前v2已获真实分段覆盖：117/150完整质量（78.0%），相对上一轮113多4题，5项质量改善0退化；原147题接口超时后获准补3题，不能称完整连续单轮。累计293/450请求，157余量结束。原评分0分26与程序拒答25分列；45专项检查通过，所有缺口未宣称解决。见[真实报告](../../experiments/train150_v2_live_summary.md)、[统一交接包](TEAM_TRAINING_HANDOFF.md)和[问题清单](TRAINING_ISSUES.md)。下文首轮记录按历史阶段保留。

用户于2026-10-30要求随机选择150题训练，余50题在后续开发中不再查看。划分已经一次性固定为 `whitebox_150_50_v1`，seed=`20261030`。使用划分前已有的189个查询族，并合并相同题文；随机打乱整组后按组大小选择恰好50题留出，剩150题训练，不读取分数决定成员，不按结果重抽样。已有族和相同题文跨集合数量均为0；启发式分组不能保证消除所有语义相似。

训练在这里指规则、参数、提示词及流程优化，不涉及更新DeepSeek权重。模板库仍固定200条；B与根目录数量均已核验，199候选没有接入。

## 划分的有效范围

此前全部200题及结果已经被看过，既有200模板的描述/示例也包含公开题。现在无法把这段历史变成未见数据。因此，这50题用于**从现在起不再参与调参**的留出评估，不能称全新未见的泛化测试。真正未见泛化应由A/C以后独立准备实体替换、语义保持改写或新增能力问题，固定参考查询，B冻结候选前不查看内容；这些也须单独标明派生集，不能冒充官方黑盒。

- 开发只读 [train.json](../../datasets/whitebox_150_50_v1/train.json) 与 `train_history.jsonl`；不读取封存题文/答案/结果，不再用全200历史回放指导修改。
- 封存文件只在一次性划分时写入，此后不打开；只读标记用于防误改，不是密码或操作系统隔离。开发入口没有留出参数，缺文件/哈希不符立即退出，不回落到原200题。
- 不通过“原200成绩减训练成绩”反推出留出成绩，不运行旧全200脚本，不按留出反馈换种子、题目或规则。
- 固定库是划分前已有知识，不能按留出题改描述、示例或默认值。新增运行时逻辑不含题号、实体或答案路由。
- 训练达到可接受水平后，先冻结源码/开关和评估协议，再由用户明确要求执行单次最终留出评估。若看反馈后继续改，此50题就成为验证集，需要新的最终测试集。

完整约定在 [B/AGENTS.md](../../B/AGENTS.md)，固定来源与哈希见[划分清单](../../datasets/whitebox_150_50_v1/manifest.json)。划分脚本拒绝覆盖已有目录；原数据、用例、评分器、执行器不修改。

## 训练的第一轮

划分后只从训练历史读取150题，完整 `query()` 流程重现固定选择/填参/精调输出，真实读取本地数据并使用原执行器与评分器：

| 条件性回放 | 完整质量答案 | 部分 / 错误 / 拒答 | 无时延诊断分，满分750 |
|---|---:|---:|---:|
| 划分时冻结基线 | 114/150（76.0%） | 2 / 8 / 26 | 567.0 |
| 多词型号修复 | 115/150（76.7%） | 2 / 7 / 26 | 573.0 |

这次只改一类失败：`productName`不再把含空格的型号截为首词。仅该字段支持无引号多词值，引号边界保留，中文条件/明确的其他字段截断，冲突值不擅选；租户、区域等其他字段保留原提取规则。训练中的1条错误得到修复，SQL不变、API筛选值恢复完整，真实结果非空；其他149题质量不变。

上述是固定历史模型输出的免费回放，不是新模型准确率、时延或留出成绩。15项专项检查通过：8项合成型号/条件边界、4项分组与加载隔离、3项真实入口的免费预检/漂移门禁。未重跑可能含留出题夹具的旧全套测试。证据：[基线回放](../../experiments/train150_v1_baseline.json)、[修复回放](../../experiments/train150_v1_model_names.json)。

用户随后批准的新真实训练集单轮已完整完成：**477/750，113完整正确（75.3%）、2部分、10错误、25拒答**；无时延560/750，293/450请求，157次余量结束不复用。Flash、150题各1次、1024输出、自动重试0；源码/配置/划分全程冻结，只用训练集，未评估封存50题，也未暂存/提交/推送。[完整报告](../../experiments/train150_v1_summary.md)、[冻结计划](../../experiments/train150_v1_live_plan.json)、[实际授权](../../experiments/train150_v1_authorization.json)。

这轮型号修复实际取得正确答案，但新的随机SQL/填参输出造成4条训练退化，净正确数低于历史基线114和固定输出候选115，不能宣称训练准确率已提高。阶段目标未达；后续围绕分组粒度、类型标签、条件所属资源及枚举合同继续改。真实新型号检查也未完成：45条源服务器中42条缺型号，其余仅1个型号，记NOT_AVAILABLE；合成边界检查不能替代真实新实体验证。

## 后续训练顺序

先以135/150（90%）完整质量答案作为阶段目标，是否可达到取决于数据、模板合同与真实模型表现，当前尚未达到。每轮选择一类训练失败，在合成反例和真实实体替换上验证，随后再看训练集回归，不用留出集决定改动。

v1有10错误、2部分、25拒答；v2分段覆盖已改善至5错误、2部分、26评分零分，其中程序拒答25。部分失败是枚举/租户合同，部分是类型ID与类型名称、比例问题与参考SQL不一致，还有复合资源能力缺口。不能通过删除筛选、猜枚举、抄训练答案或拒答全放行来宣称训练完成。B负责明确边界和流程修复，A负责给字段/关系与模板语义依据，具体待办见 [A需求清单](A_REQUESTS_TRAINING.md)。

## 免费复查

从B目录执行，输出路径须尚不存在；这些命令不调用模型、不打开封存题：

```bash
.venv/bin/python -W error::ResourceWarning -m unittest discover -s tests -p 'test_training_*.py' -v
.venv/bin/python train_replay.py --latest-live --candidate-flags --output reports/train150-v2-replay-recheck.json
.venv/bin/python train_live.py --candidate-flags
```

真实完整入口只有固定150题，没有`--case-file`、`--limit`或留出选项；仅`--run`且给定匹配的冻结计划/新输出文件才调用模型。用户已持续授权后续问题由B自行决定，有界训练实验由agent先冻结范围、来源和独立账目，不再逐轮询问，也不能伪称逐轮人工批准。划分后的训练阶段不要再运行旧的全200脚本。旧轮次命令需先恢复对应源码副本，不能在当前候选上套旧计划；v2补测已经结束，当前源码漂移时必须拒绝复用其计划。

新增`train_prompt_probe.py`仅做固定16训练题的新旧SQL精调提示词配对，最多32次refine请求，选择/填参与API输入固定。该探针没有留出入口；它的结果须与完整150题query成绩分列，见[协议与报告](../../experiments/train150_v3_prompt_notes.md)。
