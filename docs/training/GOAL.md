# 固定150题训练目标

> 目录合并更新：当前从仓库根目录工作，唯一代码在`implementation/`；训练脚本、tests、datasets和experiments均已迁到根目录。本文旧B路径和成绩属于历史阶段，当前命令以[根README](../../README.md)为准。


用户要求持续迭代，目标为原`evaluate_case`在完整连续单轮150题中计时总分至少700/750。当前未达到；无时延质量分、分段覆盖和少量精调探针分别报告，不挑选多轮最好结果拼接。

唯一开发集是`datasets/whitebox_150_50_v1/train.json`，seed20261030；50题封存不读不测，不重抽划分，不读取旧全200逐题材料。模板库固定200，不能为过题猜关系或写题号/答案路由。官方执行器、评分器、服务和用例保持不变。

每轮按以下顺序推进：

1. 从训练未通过题中确认一类原因，记录原模型/参数/API/SQL/评分证据；缺合同交A/C，B可独立证明的实现先推进。
2. 先做免费重现和必要语义反例，再冻结小范围真实复测，少次请求，独立预算，不复用旧余额。用户持续自主授权下由B决定，默认每轮最多450请求、1024输出、SDK重试0。
3. 修复有效后回归修改前冻结的已满分训练题，优先免费固定输出回放，再对新模型输出相关路径做少量真实回归。不能只挑未通过题、不看退化。
4. 候选稳定后冻结源码/开关/顺序/哈希/缓存和计时协议，完整150题连续单轮验收，核对所有请求及响应身份、实际用量和源码一致性。原计时分≥700且记录闭合才称达标。

当前证据：v2分段覆盖117/150满质量（78%），原147题运行计时514/735，不能与补测拼成连续150成绩。v3仅16题精调配对，新提示69/80无时延，2改善0退化，尚无采用新提示的完整150题结果。

下一步先应用已观察到的提示词改善做失败小集与已过题的完整query回归；并推进独立资源先聚合再组合，避免明细笛卡尔乘积。字段/状态/关系合同不明确的部分交A，参考覆盖与隐藏门禁交C，详见`A_C_NEXT_PROMPT.md`。
