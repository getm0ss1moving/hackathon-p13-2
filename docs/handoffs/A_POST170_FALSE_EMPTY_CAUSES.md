# 170 之后模板合并与误空：原因调查及 A/B 交接

**真实模型拒答率目前无法量化。49个冻结正例与98个礼貌变体是定向合成机制诊断，不是实际模型拒答概率。** 本次只发布原因交接和小型统计附件，不发布132模板、解析器或检索补丁；132仍是隔离候选，未正式交付。F03超4KB及COUNT业务门禁未决。

附件：[脱敏统计与源码指纹](A_POST170_FALSE_EMPTY_CAUSES.summary.json) · [49个能力/参数轮廓覆盖表](A_POST170_FALSE_EMPTY_CAUSES.views.csv)。不附原始运行日志、业务数据、私有fixture或封存/200逐题内容。文中实例名仅保留脱敏义务结构，完整数值结论仍归原冻结输入；本次发布未重新运行实验。

结论：目前有证据支持的是**完整查询义务被 family 命中掩盖、有限自然语言校验误拒正常措辞、候选与 B 的选择卡／view／dispatch 合同不同步**。没有可用于同条件比较的 170、160、153、141、132 模型聚合证据，本报告不能量化“模板越少，模型拒答率越高”，也不能把所有返回空值归为模型拒答。

本轮只读调查，未修改候选、检索器、B、生产文件、评分器或官方执行器。没有模型请求或业务服务请求；没有读取封存 50 或完整 200 逐题反馈；没有恢复任何已结束的 200 任务。下述 200 是模板中的来源检索轮廓数，不是评测题目反馈。

- 同参数礼貌前缀正例：0/49 通过。
- 同参数礼貌后缀正例：0/49 通过。

## 可复现的生成方法与公开材料边界

1. 固定本报告列出的B checkpoint、检索器hash与各版本候选身份。分别比较来源profile ID、文档顺序、token向量和IDF，再对每个复合问题逐项检查profile义务；canonical family命中只能作为另一项指标，不能代替完整义务覆盖。五版使用同一364条公开模板文字/合成输入协议，统计无候选、缺profile义务与canonical命中三类结果，不用这些结果推算模型拒答率。
2. 按CSV中的49个view/参数轮廓，保留每个冻结支持问法q及正确参数p不变。分别调用纯prepare检查原q、前加“麻烦帮我”的q、后加“，谢谢”的q；再生成额外密码输出、额外SQL参数键两类真不支持负控制。每个轮廓5次，共245次。正例不误空与负例应拒绝同时作为门禁，不取消原文、角色、投影或义务校验来追求通过率。
3. 该说明可生成同结构的机制控制；精确重跑245次和五版1820次仍需要来源owner保留的冻结候选、正确参数及完整输入。源码/证据指纹见摘要，私有fixture和原始日志不在本次发布范围。脱敏问题结构及CSV本身不能证明全套重跑；本次只检查报告、摘要与CSV的计数/来源一致性，没有重新执行prepare、检索或业务请求。
4. A仅负责检索层漏义务，沿用既有检索owner任务；B负责选择卡、view/schema、抽参、prepare、组合和业务执行诊断。模型选择0/错view、参数错误、prepare误拒、真不支持、合法业务空与请求/分页/schema异常必须分开记录。真实模型率比较须固定同题集、模型参数、B实现、评分器与服务条件，当前无此五版聚合证据。
